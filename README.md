# 모아 · 내 컴퓨터용 콘텐츠 스튜디오

글을 쓰고, 직접 검토한 뒤 승인하는 **로컬 프로그램**입니다. 웹사이트·SNS에 실제 업로드하는 연결은 나중에 추가합니다.

## 설치 없이 시작하기

1. [모아 로컬용 ZIP 다운로드](https://raw.githubusercontent.com/gwakwork/Contents/main/release/moa-local.zip)를 눌러 받습니다. GitHub 로그인이 필요하면 본인 계정으로 로그인합니다.
2. Mac에서는 Finder의 **다운로드** 폴더에서 `moa-local.zip`을 더블클릭해 압축을 풉니다. Safari가 자동으로 압축을 풀었다면 이 단계는 건너뜁니다.
3. `moa-local.html`을 우클릭한 뒤 **다음으로 열기 → Google Chrome 또는 Microsoft Edge**를 선택합니다. 같은 폴더의 `처음 읽어주세요.txt`에 사용 방법이 있습니다.
4. **새 콘텐츠 작성 → 임시 저장 → 검토 요청 → 미리보기·체크리스트 확인 → 최종 승인** 순서로 사용합니다.
5. 고칠 부분은 검토 의견을 적고 **수정 요청**을 누릅니다. 승인한 글을 수정하면 승인이 취소되며 다시 검토해야 합니다.

Windows와 macOS에서 HTML 파일을 여는 방식입니다. 호스팅 가입·로그인·Node.js 설치·서버 실행이 필요하지 않습니다. 처음에는 빈 작업 공간이며 **예시 콘텐츠 둘러보기**로 예시 6개를 불러올 수 있습니다. 예시는 구분 표시가 있고 별도로 정리할 수 있습니다.

채팅창에서는 ZIP **미리보기**가 지원되지 않습니다. 위의 GitHub 다운로드 주소를 사용하면 채팅의 압축 파일 미리보기 화면을 거치지 않고 파일을 받을 수 있습니다. 사용자 승인에 따라 소스와 완성 파일을 이 저장소에 함께 보관합니다.

## 글이 저장되는 곳과 백업

- 글과 검토 기록은 **현재 컴퓨터·현재 브라우저의 저장 공간(IndexedDB)**에 저장됩니다. HTML 파일 내용에 원고를 써 넣는 방식이 아닙니다.
- 같은 컴퓨터·브라우저·파일 위치를 계속 사용하세요. 브라우저를 닫아도 글이 남지만, 브라우저의 사이트 데이터를 삭제하면 글도 삭제됩니다. 시크릿·InPrivate 창은 사용하지 마세요.
- 화면 위 **백업 저장**으로 작성 중인 원고, 채널별 원고, 검토 의견, 승인 이력 전체를 JSON 파일로 보관할 수 있습니다. 편집 중인 글은 먼저 저장해야 합니다.
- 다른 컴퓨터·브라우저로 옮기거나 HTML 파일 위치를 바꾸기 전에 백업하세요. 새 환경에서 **백업 가져오기**로 복원할 수 있습니다.
- 가져오기는 기존 글을 덮어쓰지 않습니다. 동일한 글은 건너뛰며, 같은 ID의 내용이 달라졌으면 이력을 보존한 별도 **복원본**을 만듭니다. 복원본은 다시 검토해야 합니다.
- 백업 파일은 25MB 이하를 지원합니다. 브라우저 저장 공간이 부족하면 저장 성공으로 표시하지 않고 오류를 안내합니다.
- 같은 컴퓨터의 같은 브라우저를 사용하는 사람은 원고를 볼 수 있습니다. 컴퓨터 사용자 계정으로 접근을 구분하세요.

## 준비된 기능

- 제목·요약·본문 편집, 표지 스타일, 검색·상태/채널 필터·정렬·카드/리스트 보기.
- 웹사이트·인스타그램·Threads 채널 선택과 채널별 원고·글자 수 확인·미리보기.
- 작성 중 → 검토 대기 → 수정 요청 또는 승인 완료. 세 가지 체크리스트를 모두 확인해야 승인됩니다.
- 검토 의견과 변경 이력, 승인된 원고 내보내기, 전체 백업과 복원.
- 두 창에서 동시에 편집할 때 버전 충돌 검사로 최신 원고 덮어쓰기 방지.

모든 앱 코드와 디자인은 HTML 한 파일에 포함됩니다. 외부 글꼴·이미지·API에 의존하지 않습니다. 표지는 내부 관리용 디자인이며 사진 업로드·웹사이트/SNS 발행 연결은 포함하지 않습니다.

## 개발자가 파일을 다시 만드는 방법

이 아래는 개발·검증용입니다. 완성 ZIP을 사용하는 사람은 실행할 필요가 없습니다.

Node.js 24 이상과 npm을 사용합니다. 클라우드 체크아웃은 `/workspace/Contents`입니다.

```sh
npm ci
npm run build:local
```

결과는 `release/moa-local.html`, `release/처음 읽어주세요.txt`, `release/moa-local.zip`입니다. 원고나 사용자 데이터는 결과 파일에 포함하지 않습니다.

```sh
npm test           # 공유 검토 규칙과 기존 서버 저장 기능
npm run test:local # 로컬 HTML 빌드 후 사용자 흐름·백업/복원·동시 수정·브라우저 재시작 검증
```

브라우저 테스트는 시스템 `/usr/bin/chromium`을 재사용합니다. 없으면 `npx playwright install chromium`으로 공식 브라우저를 설치하거나 `CHROMIUM_PATH`를 지정하세요.

**검증의 범위:** 이 관리형 클라우드 브라우저는 `file://` 직접 열기를 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단합니다. 정책을 변경하지 않고 같은 완성 HTML을 로컬 정적 문서로 제공해 기능을 검증합니다. 테스트 주소는 문서만 제공하며 `/api`와 데이터베이스 서버가 없습니다. 그 문서 외의 네트워크 요청을 차단한 상태에서 모든 기능과 영구 브라우저 프로필의 재시작 보존을 검증합니다. 사용자 Windows/macOS의 실제 `file://` 더블클릭 실행은 아직 별도 확인이 필요합니다. 회사 관리 브라우저 등에서 로컬 HTML이 차단된다면 관리 정책을 변경하지 말고 허용된 실행 방법을 사용하세요.

개발 중 정적 로컬 문서로 확인할 때는 `node scripts/serve-local.mjs`를 사용할 수 있습니다. 파일 방식과 HTTP 방식의 저장 공간은 서로 다르므로 전환 전에 백업·가져오기를 하세요.

## 기존 서버형 개발 버전

향후 업로드 연결이나 서버 저장이 필요할 때를 위해 기존 React/Vite + Express + SQLite 버전도 유지합니다.

```sh
npm run dev        # 5173번 개발 화면과 3001번 API
npm run build      # 서버형 배포 파일
npm start          # 빌드된 화면과 API 제공
npm run test:e2e   # 별도 테스트 DB의 서버형 사용자 흐름
```

서버형은 기본적으로 `127.0.0.1:3001`에 바인딩하며 `data/studio.sqlite`에 저장합니다. 로컬 HTML의 IndexedDB와 자동 공유되지 않습니다. 로그인은 없으므로 인터넷에 직접 공개하지 마세요. `PORT`, `HOST`, `DATA_PATH` 환경 변수로 개발 설정을 바꿀 수 있습니다. `.env` 자동 로더는 없습니다.

SQLite 백업은 서버를 정상 종료한 뒤 `data` 폴더 전체를 보관하거나 SQLite의 일관된 온라인 백업 기능을 사용하세요. 실행 중 `.sqlite` 파일 하나만 복사하지 마세요.

`server/domain.mjs`의 검토 규칙과 `server/examples.mjs`의 예시는 서버형·로컬형이 공유합니다. `src/local-api.ts`는 네트워크 대신 브라우저 저장소를 사용합니다. 실제 채널 업로드는 최종 승인 및 최신 버전을 다시 확인하는 별도 연결 단계에서 구현합니다.
