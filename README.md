# Narrative

**원문 넣기 → 공식 선택 → AI 각색 → 내가 검토·수정 → 최종 승인** 순서로 사용하는 Mac 로컬 앱입니다. OpenAI API를 실제로 연결하며, 웹사이트·인스타그램·Threads에 맞는 원고를 준비합니다. 실제 업로드 연결은 추후 추가합니다.

## Mac에서 시작하기

1. [Mac용 ZIP 파일 페이지](https://github.com/gwakwork/Contents/blob/main/release/narrative-mac.zip)를 엽니다. 저장소에 접근할 수 있는 GitHub 계정으로 로그인하고 **Download raw file** 또는 다운로드 아이콘을 누릅니다.
2. Finder에서 `narrative-mac.zip`을 더블클릭해 압축을 풉니다.
3. `Narrative-Mac` 폴더 안의 **시작.command**를 더블클릭합니다. 처음 한 번은 공식 Node.js 실행 도구를 자동으로 받습니다. 직접 프로그램을 설치하거나 명령어를 입력할 필요는 없습니다.
4. 브라우저가 열리면 **AI 작업실 → AI 연결 설정**을 누릅니다.
5. [OpenAI에서 발급한 API 키](https://platform.openai.com/api-keys)를 넣고 저장합니다. 키를 채팅에 보내지 마세요. **ChatGPT Plus·Pro 구독과 API 사용료는 별도**이며, API 계정에 사용 가능한 잔액·한도가 필요합니다.
6. 원문을 붙여 넣고 공식·말투·분량·채널을 골라 **AI로 각색하기**를 누릅니다.
7. 결과와 원문을 비교하고 **이 결과를 검토함으로 보내기**를 누릅니다. 검토함에서 글을 고치고 세 가지 확인 항목을 체크한 뒤 **최종 승인**합니다.

Apple Silicon과 Intel Mac, **macOS 13.5 이상**을 지원합니다. AI 각색과 최초 실행 도구 다운로드에는 인터넷이 필요합니다. 사용하는 동안 열린 터미널 창을 유지하고, 종료하려면 그 창에서 **Control+C**를 누릅니다. 이미 실행 중이면 기존 Narrative를 엽니다. 다른 프로그램이 같은 포트를 사용하면 안내 후 중단합니다.

Mac이 실행을 막으면 **시스템 설정 → 개인정보 보호 및 보안**의 안내를 확인하고 신뢰하는 이 파일에 대해서만 허용하세요. 보안 기능 전체를 끄지 마세요. 실행 권한만 없다는 오류이면 터미널에서 `bash`와 공백을 입력한 뒤 `시작.command`를 끌어 넣고 Enter를 누를 수도 있습니다. 세부 안내는 압축 안의 `처음 읽어주세요.txt`에 있습니다.

이전 원고 관리용 HTML과 AI 실행 버전은 별도 파일입니다. AI 기능을 사용하려면 **narrative-mac.zip**을 사용하세요. GitHub의 404 화면은 로그인한 계정의 저장소 접근 권한도 확인해야 합니다. 클라우드에서 Git 접근이 성공한 것으로 사용자 브라우저의 다운로드 성공을 보장하지는 않습니다.

## 기본 공식

| 공식        | 글을 정리하는 순서                         |
| ----------- | ------------------------------------------ |
| AIDA        | 주목 → 관심 → 욕구 → 행동                  |
| PAS         | 문제 → 공감 → 해결                         |
| 정보 전달형 | 핵심 요약 → 상세 설명 → 활용 방법 → 마무리 |
| 스토리텔링  | 상황 → 변화 → 의미 → 마무리                |
| 나만의 공식 | 직접 입력한 순서와 규칙                    |

말투는 친근하게·전문적으로·간결하게, 본문 분량은 짧게·보통·길게를 선택할 수 있습니다. 대상 독자와 추가 요청도 입력할 수 있습니다. 웹사이트 본문과 선택한 SNS 원고를 따로 생성하며, 공식 적용 요약·바꾼 점·직접 확인할 사항을 표시합니다. 원문이나 옵션을 바꾼 뒤에는 새로 각색해야 이전 결과를 검토함으로 보낼 수 있습니다.

## 저장과 백업

- 원고, AI 작업 기록, 설정은 **`~/Library/Application Support/MoaContentStudio/`**에 보관합니다. 프로그램 폴더를 새 버전으로 바꿔도 이 데이터는 유지됩니다.
- API 키는 위 폴더의 `ai-settings.json`에 현재 사용자만 읽고 쓸 수 있는 권한으로 보관합니다. **암호화 저장은 아닙니다.** 브라우저 저장 공간, 원고 백업, GitHub에 키를 넣지 않습니다.
- 키 저장은 유료 요청을 보내지 않으므로 ‘API 키 저장됨’ 표시는 연결 성공 증명이 아닙니다. **AI로 각색하기**를 눌렀을 때 실제 요청을 보냅니다. 취소하더라도 이미 처리된 API 사용량은 청구될 수 있습니다.
- 같은 작업 번호의 요청은 재사용하고, 오류나 앱 재시작 시 AI 요청을 자동 반복하지 않습니다. AI 작업은 한 번에 하나만 실행합니다. 완성된 결과는 이 컴퓨터에 저장되며 최근 100개를 화면에 표시합니다.
- 화면 위 **백업 저장**은 저장한 원고·검토 이력·채널별 원고·검토함으로 보낸 AI 원문을 JSON으로 내보냅니다. API 키와 아직 검토함으로 보내지 않은 AI 작업은 포함하지 않습니다.
- **백업 가져오기**로 기존 HTML 버전의 백업도 옮길 수 있습니다. 동일한 원고는 건너뛰고, 현재 원고와 다른 내용은 별도 **복원본**으로 추가합니다. 복원본은 다시 검토해야 합니다. 파일은 25MB 이하를 지원합니다.
- 전체 AI 작업 기록과 설정까지 보관하려면 앱을 정상 종료한 뒤 위 폴더 전체를 복사하세요. 키가 포함되므로 안전하게 관리하세요. 실행 중 SQLite 파일 하나만 복사하지 마세요.

이전 `moa-local.html`의 글은 그 화면에서 **백업 저장**한 뒤 새 앱의 **백업 가져오기**로 옮깁니다. 이전 파일의 원고는 해당 컴퓨터·브라우저 저장 공간에 있습니다.

## 검토와 발행

AI 결과는 자동 승인되지 않습니다. 검토함에서 내용·사용 권리·채널별 원고를 모두 확인해야 승인할 수 있습니다. 승인 후 글을 수정하면 승인이 초기화됩니다. 원문에 없는 사실을 만들지 않도록 요청하지만 AI 결과의 정확성은 직접 확인해야 합니다. 원문과 요청은 생성 시 OpenAI로 전송됩니다. Responses API 요청에는 `store: false`를 사용하며, 이것이 서비스의 모든 보존 정책을 없애는 것은 아닙니다.

웹사이트·SNS 업로드는 아직 연결하지 않았습니다. 승인된 원고를 내보내어 보관할 수 있습니다. 검색·필터·정렬, 예시 6개, 검토 의견, 변경 이력, 동시 수정 충돌 검사도 제공합니다.

## 개발과 검증

Node.js 24 이상과 npm을 사용합니다. 클라우드 체크아웃은 `/workspace/Contents`입니다.

```sh
npm ci
npm run dev          # 개발 화면과 API
npm run build
npm start            # 빌드한 화면과 API
npm test             # 검토·저장·AI HTTP 계약·오류·중복 요청·키 보호·백업
npm run test:e2e     # 기존 원고 관리 흐름, 데스크톱/모바일
npm run test:ai      # AI 각색→검토→승인 흐름, 데스크톱/모바일
npm run build:mac    # 실행 준비물이 포함된 Mac용 ZIP
```

실제 연동은 `https://api.openai.com/v1/responses`의 JSON Schema structured output을 사용합니다. 기본 모델은 `gpt-4.1-mini`이며 화면에서 사용 가능한 모델 이름으로 바꿀 수 있습니다. 테스트는 **가짜 OpenAI 서버/응답**을 명시적으로 주입해 검증합니다. 제품 실행 코드에 모의 결과를 켜는 옵션은 없습니다. 실제 API 키와 잔액이 없어 **유료 생성·모델 품질은 시험하지 않았습니다**. 실제 Mac에서의 더블클릭 실행도 별도 확인이 필요합니다. 압축 파일의 서버·화면은 Linux에서 풀어 실행해 검사합니다.

Mac 패키지는 고정된 lockfile로 설치한 순수 JavaScript 의존성과 빌드 결과를 포함합니다. 실행 도구는 Node.js **v24.22.1** 공식 Mac 배포물을 CPU에 맞게 내려받고 코드에 고정한 공식 SHA-256으로 확인한 뒤 사용합니다. TLS·체크섬 검증을 끄지 않습니다.

브라우저 테스트는 `/usr/bin/chromium`이 있으면 재사용합니다. 없으면 `npx playwright install chromium`으로 공식 브라우저를 설치하거나 `CHROMIUM_PATH`를 지정합니다. 기본 주소는 이 컴퓨터에서만 접속할 수 있는 `127.0.0.1:3001`이며 로그인 없는 로컬 앱을 인터넷에 공개하지 않습니다. 개발 시 `PORT`, `HOST`, `DATA_PATH`를 지원하고 `.env` 자동 로더는 없습니다. 개발 환경의 `MOA_OPENAI_API_KEY` 또는 `OPENAI_API_KEY`가 있으면 로컬 설정 키보다 우선합니다. `MOA_OPENAI_MODEL`은 모델을 고정합니다. 키 값을 로그나 소스에 쓰지 마세요.

AI 없이 원고만 관리하는 기존 단일 HTML도 유지합니다.

```sh
npm run build:local
npm run test:local
```

결과는 `release/narrative-local.html`과 `release/narrative-local.zip`입니다. 기존 `moa-local` 파일 이름도 호환용으로 제공합니다. 이 모드는 네트워크 대신 IndexedDB에 저장하며 AI 연결은 지원하지 않습니다. 클라우드 관리형 브라우저는 `file://`를 정책으로 차단하므로 정책을 바꾸지 않고 같은 완성 HTML만 정적으로 제공해 검증합니다. 해당 문서 외의 네트워크 요청을 차단하고 사용 흐름·백업·동시 수정·브라우저 재시작 보존을 검사합니다. Mac에서 실제 파일 더블클릭은 별도 확인이 필요합니다.

디자인 기준은 `npx getdesign@latest add apple`로 가져온 [DESIGN.md](DESIGN.md)입니다. 시스템 글꼴, 흰색·회색 화면, 파란 버튼과 간결한 입력·검토 화면에 적용했습니다. 기존 저장 경로와 백업 형식은 이전 원고를 그대로 읽기 위해 유지합니다.
