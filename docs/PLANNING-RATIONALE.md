# Narrative 기획 프로세스의 설계 근거

Narrative의 기획 기능은 창작자가 **누구에게, 왜, 무엇을 전하고, 어떤 변화로 성공을 확인할지** 정리하는 도구다. 기획안을 먼저 저장하고 그 결정을 AI 각색에 전달한다. 최종 콘텐츠의 사실 확인과 승인은 별도 검토에서 수행한다.

아래 연구는 설계의 근거다. Narrative의 단계 수, 선택지 수, 완성률 개선 효과를 직접 검증한 연구는 아니다. 선택지를 줄이면 모든 상황에서 결과가 좋아진다거나, 기획 완료가 콘텐츠의 성공을 보장한다고 주장하지 않는다.

## 전문 기획의 최소 흐름

크리에이티브 브리프의 목적·독자·메시지·근거·요청 행동·측정 항목을 순서대로 정리한다. 구성 공식은 목적을 정한 **뒤에** 선택한다. AIDA나 PAS를 정하는 것이 콘텐츠의 목적을 정하는 일을 대신해서는 안 된다.

| 단계        | 결정할 것                                          | 우선 제공할 선택 방식                                                                             | 짧게 필요한 입력                                 |
| ----------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 목적과 목표 | 무엇을 바꾸고 어떻게 확인할 것인가                 | 알리기 / 이해·도움 / 신뢰·관계 / 행동 유도 / 탐구·표현, 목적별 확인 기준과 시점                   | 주제·기획 이름, 수치 목표는 필요한 경우만        |
| 독자와 필요 | 누구의 어떤 상황을 다루는가                        | 처음 접함 / 관심이 있음 / 비슷한 고민의 동료 / 잠재·기존 고객 / 직접 입력, 이해 단계, 독자의 필요 | 선택지에 없는 구체적인 독자·필요                 |
| 핵심 메시지 | 무엇 하나를 남길 것인가                            | 문제 해결 / 경험 / 비교·판단 / 핵심 정리 / 질문·관점                                              | 핵심 메시지 한 문장, 근거·확인할 자료, 예상 질문 |
| 행동과 채널 | 독자에게 어떤 다음 행동을 요청할 것인가            | 기억하기 / 저장하기 / 실행하기 / 대화하기 / 더 알아보기 / 직접 입력, 준비할 채널                  | 선택지에 없는 다음 행동                          |
| 구성과 표현 | 어떻게 전달할 것인가                               | 형식, 말투, 분량, 목적에 따른 수정 가능한 공식 제안                                               | 나만의 공식을 사용할 때 규칙 입력                |
| 실행과 점검 | 어떤 상황에서 무엇을 실행하고 무엇을 확인할 것인가 | 실행 상황과 다음 작업, 목적·독자·근거·실행 가능성 확인                                            | 선택지에 없는 “○○하면, ○○한다” 실행 계획         |

이 표는 단계의 역할을 정의한다. 실제 화면에서는 서로 밀접한 항목을 합치거나 질문을 다음 단계로 옮겨도 된다. 질문을 나누는 단위는 심리학의 고정된 숫자가 아니라 실제 작업과 사용성 검증으로 정한다.

### 완료 조건

- 주관적인 목적·핵심 독자·핵심 메시지는 사용자가 직접 정한다. 미리 선택된 첫 옵션으로 결정을 대신하지 않는다.
- 주요 목적, 독자의 필요, 핵심 메시지, 확인할 성공 기준이 구체적이어야 기획을 확정한다. 수치 목표가 없다는 이유만으로 탐구형·정보형 기획을 막지 않는다.
- 근거가 없는 경우 “확인 필요”로 남긴다. 근거 종류를 선택한 것과 실제 근거를 확보한 것을 구분한다.
- 요약에서 모든 결정을 확인하고 해당 단계로 돌아가 수정할 수 있다. 목적을 바꾸면 관련 결정의 재확인이 필요함을 표시하고, 임의로 다른 선택을 덮어쓰지 않는다.
- 기획 확정은 콘텐츠의 사실 검증이나 발행 승인이 아니다. AI 초안 역시 인간의 최종 검토를 거친다.

## 인지심리학·행동경제학을 화면에 적용하는 방식

## 서비스 문구와 선택권

서비스 화면에는 이론 이름이나 긴 설명을 넣지 않는다. “목적”, “독자”, “핵심 메시지”, “성공 기준”, “다음”, “기획 확정” 같은 작업 중심 이름을 쓴다. 필요한 맥락 도움은 해당 질문 옆 한 문장 또는 접힌 도움말로 제공한다.

선택이 없는 상태를 잘못된 답으로 평가하지 않는다. 저장·이어 쓰기·이전 단계 이동을 지원한다. 진행 표시는 실제 작성한 단계와 저장 상태를 보여주며 가짜 완료율이나 임의의 “기획력 점수”를 만들지 않는다. 입력이 적어도 확정한 것처럼 보이는 기만적인 기본 선택을 두지 않는다.

추천은 강요가 아니다. 정보 전달형은 설명·활용 중심, 스토리텔링은 경험·관점 중심, AIDA/PAS는 적절한 행동 제안 중심의 **편집적 제안**이다. 공식별 성과가 과학적으로 보장되는 것처럼 표현하지 않는다. PAS를 공포·수치심 조장에 사용하거나 AIDA에 허위 희소성·가짜 후기·없는 효능을 추가하지 않는다.

기획을 확정하거나 AI 입력으로 옮기는 행위 자체가 유료 요청을 실행하지 않게 한다. OpenAI로 전송할 내용과 비용 발생 시점은 기존의 명시적 생성 동작과 연결한다.

## 적용 후 확인할 것

개발 검사는 저장·복원·동시 수정 충돌, 목적 변경 시 재검토, 기획의 AI 전달, 원문과 기획 보존, 수치 없는 기획과 실제 유료 요청 없는 기획 흐름을 확인한다.

제품 검증에서는 다음을 측정한다. 수집·전송 기능을 사용자의 동의 없이 추가하지 않고, 초기에는 사용성 인터뷰와 로컬 관찰로 확인할 수 있다.

- 처음 기획하는 사용자가 목적·독자·성공 기준을 자기 말로 설명할 수 있는가.
- 목표와 핵심 메시지·요청 행동이 서로 맞는가. 독립적인 검토 기준으로 비교한다.
- 첫 저장·확정까지 걸리는 시간, 단계별 이탈, 뒤로 이동하는 이유가 무엇인가.
- 선택지 밖의 의도를 ‘직접 입력’으로 충분히 표현할 수 있는가.
- 추천을 그대로 수락하는 비율만 높아진 것인지, 사용자가 추천 이유를 이해하고 바꿀 수 있는지 구분한다.
- AI 결과가 확정한 기획의 목적·독자·근거·제약을 따르는가. 문장 완성도와 기획 충실도를 별도로 본다.

개선 효과를 주장하려면 비교 가능한 과제와 전후 또는 대조군 평가가 필요하다. 내부 검사를 통과했다는 사실만으로 기획 품질 향상률이나 인지부하 감소율을 제시하지 않는다.
